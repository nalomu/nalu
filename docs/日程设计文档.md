# 日程设计文档

## 1. 界面概述

日程页面用于管理带时间属性的任务，支持按日、周、月三种日历视图查看计划，支持在日程页新建、编辑、完成、删除任务，并通过系统通知提供临近提醒。

当前方案以 `tasks` 为新日程能力的唯一事实来源：

1. 日程页是任务的时间视图，负责时间安排。
2. 任务页是任务的组织视图，负责分组、分列、排序和执行状态。
3. 旧 `schedules` 表和旧命令保留用于兼容历史数据，不再作为新建日程的写入来源。

页面基于 Vue 3 + TypeScript 实现，通过 Tauri command 调用 Rust 后端读写 SQLite 本地数据。普通浏览器 `localhost` 开发环境下使用 localStorage fallback，便于在非 Tauri 环境中验证日程页和任务页联动。

## 2. 设计目标

1. 日程页面以日历形式展示任务计划。
2. 支持日、周、月三种展示级别。
3. 日视图和周视图按小时维度展示任务，任务按真实时间段连续渲染。
4. 月视图按日期维度展示任务摘要。
5. 日程页支持新建、修改、完成、删除任务。
6. 日程页与任务页保持同步，同一任务在两个页面操作后状态一致。
7. 任务支持计划开始时间、计划结束时间、提醒分钟数、实际完成时间和重复属性。
8. 重复任务默认不重复，可选择每天、每周、每月、每年。
9. 任务页默认隐藏未来未完成重复实例，但日程页仍展示未来计划。
10. 删除任务和移出日程必须是两个独立动作，避免误删任务页任务。

## 3. 页面布局

### 3.1 顶部工具栏

顶部工具栏采用三列布局：

1. 左侧：页面标题“日程”和新增任务按钮。
2. 中部：居中的日期导航和当前视图范围。
3. 右侧：日、周、月视图切换。

日期导航包含：

1. 上一段：日视图切换到前一天，周视图切换到上一周，月视图切换到上个月。
2. 今天：回到当前日期。
3. 下一段：日视图切换到后一天，周视图切换到下一周，月视图切换到下个月。
4. 当前范围标题：例如 `2026年6月17日`、`2026年6月15日 - 6月21日`、`2026年6月`。

新增任务按钮位于左侧标题内容右侧，点击后打开浮动编辑面板，默认使用当前视图锚点日期和默认任务名称。右侧只保留视图切换，避免新增按钮挤压切换区域。

### 3.2 日视图

日视图以单日 24 小时为纵轴展示：

1. 左侧固定小时刻度，范围 `00:00` 到 `23:00`。
2. 右侧为当天时间网格，每小时一行。
3. 任务根据 `scheduled_start_at` 和 `scheduled_end_at` 定位到对应时间段。
4. 当前日期为今天时展示当前时间指示线。
5. 点击小时单元格空白区域，立即创建默认名称的一小时任务，并打开浮动编辑面板。
6. 拖选一段时间后，松开指针立即创建默认名称任务，并打开浮动编辑面板；不弹出居中的保存框。
7. 已有任务块只占用单元格左侧主要区域，右侧保留空白点击/拖选区，用于继续新建任务。
8. 任务块在单元格内使用固定水平和垂直缩进，避免视觉上越过小时格内边界。
9. 首次打开日视图或切换到日视图时，默认滚动定位到当前时间点所在小时单元格附近。

### 3.3 周视图

周视图以一周七天为横轴、24 小时为纵轴展示：

1. 表头展示周一到周日，包含日期和星期。
2. 当前日列高亮，便于识别今天。
3. 左侧显示小时刻度。
4. 每个日期列内按时间段展示任务。
5. 点击某天某小时单元格，立即创建该天默认名称的一小时任务，并打开浮动编辑面板。
6. 在同一天内拖动，松开后立即创建当天时间段任务，并打开浮动编辑面板。
7. 跨天拖动时，松开后立即创建跨天任务，开始时间为拖动起点，结束时间为拖动终点。
8. 跨天任务在周视图中按天拆成多个视觉片段展示，但仍对应同一个任务。
9. 周视图事件覆盖层保持完整七列宽度，与表头和小时网格对齐；只压缩单个任务块宽度来保留右侧新建区域，不能压缩整层事件网格。
10. 首次打开周视图或切换到周视图时，默认滚动定位到当前时间点所在小时单元格附近。

周起始日采用周一，符合中文用户习惯。

### 3.4 月视图

月视图以日期为粒度展示：

1. 使用 7 列日历网格，周一作为每行起始。
2. 首行补齐上月尾部日期，末行补齐下月头部日期。
3. 当前月份日期正常显示，非当前月份日期弱化显示。
4. 今天日期明显标识。
5. 每个日期格内展示当日最多 3 条任务摘要。
6. 超出 3 条时展示 `+N` 更多提示。
7. 日期格空白处点击后打开新建任务弹窗，默认新建当天 `00:00-23:59` 任务。
8. 点击已有任务摘要打开编辑弹窗，不切换到日视图。
9. 删除等高风险操作不在月格内直接暴露，避免界面拥挤。

### 3.5 空状态

1. 日视图：当天无任务时，在网格区域中显示轻量空状态“当天暂无日程”。
2. 周视图：整周无任务时显示“本周暂无日程”；单日为空时保持网格为空。
3. 月视图：当月无任务时仍展示完整月历，不额外遮挡日历。

## 4. 任务编辑弹窗

### 4.1 入口

日程页提供四种新建入口：

1. 顶部新增按钮：默认使用当前视图锚点日期，打开浮动编辑面板，标题预填默认任务名称。
2. 日/周视图点击小时单元格：立即创建默认名称任务，开始时间为选中小时，默认结束时间为开始时间后一小时。
3. 日/周视图拖选时间段：松开后立即创建默认名称任务，时间段为拖选的开始和结束时间；周视图拖选可跨天。
4. 月视图点击日期格空白处：打开浮动编辑面板，预填默认任务名称和当天 `00:00` 到 `23:59`。

点击已有任务卡片或月视图任务摘要时，打开浮动编辑面板。

### 4.2 字段

浮动编辑面板支持：

1. 标题。
2. 任务分列。
3. 开始日期和时间。
4. 结束日期和时间。
5. 提前提醒分钟。
6. 重复选择，默认“不重复”，可选“每天、每周、每月、每年”。
7. 完成状态。
8. 移出日程按钮。
9. 删除任务按钮。

任务分列选择用于决定任务在任务页中的具体列归属：

1. 选项来源于任务页现有分组内的列，即 `task_columns`。
2. 下拉展示为“外层分组 / 分列名称”，例如 `2026-06-17 / 重要`。
3. 日期类型分组和非日期类型分组下的列都可选择。
4. 日/周拖选创建时，默认选择任务开始日期分组下的首列。
5. 月视图点击日期创建时，默认选择点击日期分组下的首列。
6. 顶部新增按钮创建时，默认选择当前视图锚点日期分组下的首列。
7. 编辑已有任务时，默认选择当前任务 `column_id` 对应的列。
8. 保存后同时更新 `tasks.column_id` 和该列所属的 `tasks.project`。
9. 如果目标日期分组尚不存在列，则保存时自动创建默认列后落入该列。

浮动编辑面板替代居中遮罩弹窗，避免拖选创建后中断日历上下文。点击或拖选创建出来的任务会先以默认名称落库，用户可以在浮动面板继续修改标题、时间、提醒和重复规则。

### 4.3 校验

1. 标题不能为空。
2. `scheduled_start_at` 必须小于或等于 `scheduled_end_at`。
3. 任务时间段必须保留具体小时分钟。
4. 月视图新建任务保存为当天 `00:00:00` 到 `23:59:00`。
5. 跨天任务允许存在，周视图按跨越日期拆分展示。

### 4.4 删除与移出日程

删除任务：

1. 删除 `tasks` 记录。
2. 任务页和日程页都会移除。
3. 确认文案必须说明“删除后任务页和日程页都会移除”。

移出日程：

1. 不删除 `tasks` 记录。
2. 清空时间字段和重复关联字段。
3. 保留任务原有 `project`、`column_id`、`position`。
4. 任务页继续保留任务。
5. 日程页不再显示该任务。

### 4.5 拖动已有任务修改时间

日视图和周视图支持直接拖动已有任务块修改时间：

1. 拖动任务主体：保持任务持续时长不变，整体移动开始和结束时间。
2. 拖动任务顶部边缘：调整开始时间，结束时间不变。
3. 拖动任务底部边缘：调整结束时间，开始时间不变。
4. 周视图拖动任务主体时，允许跨日期列移动，保持持续时长不变。
5. 拖动吸附到 10 分钟刻度，与拖选新建任务的时间粒度一致。
6. 调整后的最小持续时间为 10 分钟。
7. 拖动到底部 `24:00` 时，内部优先保存为次日 `00:00:00`，展示时按当天结束边界渲染。
8. 拖动中显示半透明预览块，预览块展示新的时间范围。
9. 拖动过程中不打开编辑面板，松开后立即保存。
10. 保存失败时恢复原位置，并显示页面内轻量错误提示。
11. 指针移动距离小于拖拽阈值时，仍按点击打开编辑面板处理。
12. 指针移动距离达到阈值后，进入拖动修改时间模式，不触发点击编辑。
13. 完成按钮、删除按钮、编辑按钮等内部控件阻止拖动事件冒泡。

拖动重复任务实例时默认只修改当前实例：

1. 保存传参使用 `scope: 'single'`。
2. 当前实例标记为 `recurrence_detached = true`。
3. 不批量修改同一系列未来实例。
4. 如后续需要“这一项及未来”，再增加独立确认交互。

### 4.6 日程页多选与批量操作

日程页支持对日程任务块进行多选和批量删除：

1. macOS 按住 `Cmd` 点击任务块切换选中状态。
2. Windows 按住 `Ctrl` 点击任务块切换选中状态。
3. 日视图、周视图和月视图任务摘要都支持多选。
4. 选中后显示批量操作条，展示已选数量。
5. 批量操作条仅提供批量删除和清空选择。
6. 批量删除删除选中的真实任务，任务页和日程页同步移除。
7. 按 `Esc` 清空选区。
8. 开始拖动某个任务调整时间时，自动清空当前多选状态，避免拖动和批量选择状态冲突。

## 5. 任务页同步规则

### 5.1 默认分组

任务默认分组统一改为任务日期：

1. 日程页新建任务时，默认分组为任务开始日期，格式为 `YYYY-MM-DD`。
2. 月视图点击日期新建任务时，默认分组为点击日期。
3. 顶部新增按钮新建任务时，默认分组为当前视图锚点日期。
4. 任务页新增任务时，默认分组为当天日期。
5. 如目标日期分组不存在，后端自动创建该分组及默认列。
6. 重复任务生成多个实例时，每个实例进入其自身发生日期对应的分组。
7. 任务页在某个已有非日期分组或列中新增任务时，继续使用当前分组，尊重用户原有看板习惯。

### 5.2 分组展开

任务页分组按类型区分默认展开状态：

1. 日期类型分组：分组名符合 `YYYY-MM-DD`。
2. 今天日期分组默认展开。
3. 非今天日期分组默认收起，包括过去日期和未来日期。
4. 非日期类型分组保持用户原有折叠习惯，继续读取本地保存的展开/收起状态。
5. 用户手动展开或收起任意分组后，继续保存到 localStorage。

### 5.3 日期归属修复

任务页需要对历史数据、浏览器 fallback 数据和异常列数据做容错：

1. 任务有 `scheduled_start_at` 时，任务页日期分组以计划开始日期为准。
2. 后端 `get_board` 在返回看板前修复异常归属，确保带计划时间的任务有有效 `project`、`column_id` 和 `position`。
3. 前端 localStorage fallback 在构建本地看板时不依赖旧 `project`，而是通过 `scheduled_start_at` 计算分组。
4. 今天日期分组仍默认展开；修复后的今天任务应立即出现在今天分组中。
5. 修复逻辑不影响用户在非日期分组内手动新增的普通任务；无计划时间的任务仍按原 `project` 展示。
6. 修复过程只调整任务页组织归属，不改变任务时间、完成状态和重复系列字段。

### 5.4 未来重复实例

任务页默认隐藏未来未完成重复实例：

1. 默认不展示 `recurrence_series_id IS NOT NULL` 且 `scheduled_start_at > today 23:59` 且 `done = 0` 的任务。
2. 这些任务仍然在日程页展示。
3. 当这些任务进入当天后，任务页展示它们。
4. 提供“显示未来重复任务”开关，默认关闭。
5. 开关开启后，未来重复任务显示在对应日期分组中。
6. 日期类型分组仍按今天展开、其他日期收起的规则处理。
7. 任务页搜索默认不包含隐藏的未来重复任务；打开开关后再纳入搜索。
8. 开关状态持久化到 localStorage。
9. 默认隐藏未来重复任务时，由未来重复实例自动产生、且没有其他可展示任务的未来日期分组也不展示，避免任务页出现空分组；打开“显示未来重复任务”后再展示这些日期分组。
10. “显示未来重复任务”开关收纳在任务页右上角设置按钮的浮动面板中，不占用任务页顶部主操作区。

### 5.5 任务页 Cmd 多选与批量处理

任务页支持按住 `Cmd` 多选任务，并对选中任务批量处理；Windows 或非 macOS 环境可兼容 `Ctrl`：

1. `Cmd + 点击` 任务卡片时，切换该任务选中状态。
2. 再次 `Cmd + 点击` 已选任务时取消选中。
3. 普通点击任务保持现有单任务编辑或操作逻辑。
4. 被选中任务卡片显示主色描边、轻量背景和选中标识。
5. 页面底部或右下方显示批量操作浮动栏，并展示已选数量。

以下行为清空选区：

1. 点击空白区域。
2. 按 `Esc`。
3. 批量操作完成后。
4. 切换搜索条件。
5. 切换“显示未来重复任务”开关。
6. 页面重新加载。

首期批量动作包括：

| 动作 | 说明 | 是否需要确认 | 是否支持撤销 |
|---|---|---|---|
| 批量完成 | 将所选任务标记为完成 | 否 | 否 |
| 批量取消完成 | 将所选任务标记为未完成 | 否 | 否 |
| 批量删除 | 删除所选任务 | 是 | 是 |
| 批量移动到分组/分列 | 将所选任务移动到指定分组的指定列 | 否 | 否 |

批量删除需要返回任务快照，删除后展示页面内 toast，5 秒内可撤销。撤销时恢复任务到原分组、原分列和原排序位置。

任务页允许跨分组、跨分列多选：

1. 批量完成、取消完成和删除直接作用于所有选中任务。
2. 批量移动需要用户选择目标分组和目标分列。
3. 移动后目标列按选中任务原展示顺序追加到列末尾。
4. `Cmd` 点击只切换选中，不启动拖拽。
5. 批量移动首期通过浮动栏操作，不做多任务拖拽。
6. 批量操作涉及重复任务时，默认只操作选中的真实任务实例，不扩散到整个重复系列。

### 5.6 今天定位浮动按钮

任务页新增浮动按钮，用于快速定位到当天日期分组：

1. 按钮固定在任务页面右下角或右侧中下位置。
2. 按钮文案建议为“今天”，也可以仅使用日历图标并提供 tooltip。
3. 按钮在非搜索状态下常驻显示，确保用户始终可以快速回到今天分组。
4. 搜索状态下按钮隐藏，避免滚动目标和搜索结果冲突。
5. 点击后如果今天日期分组存在，则平滑滚动到该分组。
6. 如果今天分组被收起，先展开再滚动。
7. 如果今天分组不存在，创建本地空分组展示结构或滚动到默认今天占位分组。
8. 今天分组不能被历史已完成日期分组隐藏规则过滤。

### 5.7 历史已完成日期分组自动隐藏

任务页默认隐藏已经处理完成的历史日期分组，减少历史任务对当前视图的干扰。

隐藏条件必须同时满足：

1. 分组名称为默认日期类型，格式为 `YYYY-MM-DD`。
2. 分组日期早于今天。
3. 分组内没有未完成任务。
4. 分组可以是已完成任务分组，也可以是任务删除后的空分组。
5. 当前不在搜索状态。
6. 用户没有打开“显示历史已完成日期分组”开关。

不隐藏以下分组：

1. 非日期类型分组。
2. 今天或未来日期分组。
3. 分组内仍有未完成任务。
4. 搜索状态下匹配到的分组。
5. 用户打开“显示历史已完成日期分组”开关后的历史已完成日期分组。

“显示历史已完成日期分组”默认关闭，状态持久化到 localStorage，例如 `nalu-show-completed-past-date-groups`。该开关收纳在任务页右上角设置按钮的浮动面板中，与“显示未来重复任务”放在同一组展示设置内。任务列和任务是独立数据，任务删除后列记录可以保留；关闭该开关时，过去日期下 `0/0` 的空分组和空任务列也不展示，避免用户误以为仍存在任务。如果第一版暂不增加开关，也必须保证搜索时能找到历史已完成任务，避免用户误以为数据丢失。

## 6. 重复任务

### 6.1 生成策略

重复任务采用“系列规则 + 真实任务实例”的策略：

1. 用户选择 `none` 时，只创建一条普通任务。
2. 用户选择 `daily`、`weekly`、`monthly`、`yearly` 时，创建一个 `recurrence_series` 系列记录。
3. 后端生成当前任务及未来任务实例，均写入 `tasks` 表。
4. 默认生成未来 1 年内的任务实例，单次最多 100 条，以较小值为准。
5. 每条实例都有独立的 `id`、`project`、`column_id`、`position`、`scheduled_start_at`、`scheduled_end_at`。
6. 每条实例共享同一个 `recurrence_series_id`，并写入递增的 `recurrence_sequence`。
7. 每条实例的 `project` 按该实例发生日期生成，格式为 `YYYY-MM-DD`。
8. 日程页和任务页都读取真实实例，不在前端临时展开虚拟任务。
9. 100 条不是重复规则的生命周期上限，而是单次生成或补生成的安全上限。

### 6.2 滚动补生成

为避免一次性生成无限任务，采用有限窗口和补生成机制：

1. 创建重复任务时生成未来 1 年或最多 100 条实例。
2. 打开日程页或应用启动时只检查 `active = 1` 的重复系列。
3. 如果某个系列最后一条实例距离当前日期超过 30 天，不补生成。
4. 如果某个系列最后一条实例已经进入未来 30 天内，继续往后补生成。
5. 每次补生成仍然最多 100 条，并以未来 1 年为窗口上限。
6. 已停用系列、已清空系列关联的任务不参与补生成。
7. 已脱离实例不参与批量更新，也不影响系列补生成。
8. 补生成前必须按 `recurrence_series_id + recurrence_sequence` 检查实例是否已存在，避免重复插入。
9. 数据库层使用唯一索引保证多次启动、多次打开日程页不会生成重复实例。

### 6.3 取消重复

仅取消这一项重复：

1. 当前任务保留。
2. 当前任务解除重复系列关系。
3. 其他实例不受影响。
4. 当前任务更新为：
   - `repeat_type = 'none'`
   - `recurrence_series_id = NULL`
   - `recurrence_sequence = NULL`
   - `recurrence_origin_at = NULL`
   - `recurrence_detached = 0`

取消这一项及未来重复：

1. 当前任务保留并转为普通任务。
2. 当前及未来同系列实例解除重复系列关系。
3. 历史任务保留。
4. 已完成任务保留。
5. `recurrence_series.active = 0`，后续不再补生成该系列。

推荐默认使用“当前任务保留，未来未完成实例删除，历史和已完成实例保留”的处理方式。这样符合用户对“以后不再重复”的直觉，同时不会破坏已经发生的任务记录。

## 7. 时间段渲染

### 7.1 定位规则

日/周视图使用覆盖层按分钟计算卡片位置：

1. `top` 由任务在当天的可见开始分钟计算。
2. `height` 由可见结束分钟减去可见开始分钟计算，并保留最小高度。
3. 跨小时任务渲染为连续卡片，不在每个小时格重复展示。
4. 同一天内重叠任务使用 lane 机制横向分栏，避免互相覆盖。
5. 跨天任务按每天可见范围拆分为视觉片段，同一任务仍对应一条 `tasks` 数据。

### 7.2 单元格边界

1. 日程块宽度按分栏宽度再乘以预留比例，默认只占日期列左侧主要区域。
2. 右侧空白区域用于在已有任务旁继续点击或拖选新建任务。
3. 日程块样式由统一定位函数计算，包含单元格内水平缩进、垂直缩进、最小宽度和最小高度。
4. 跨天片段从当天之前开始时不增加顶部缩进，延续到当天之后时不增加底部缩进，以保持跨天视觉连续。
5. 周视图事件层必须与七天表头和小时网格保持同一列宽；右侧新建区域只能通过压缩单个事件块实现。
6. 日/周事件块外层不应使用额外 padding 造成视觉越界，边界缩进应统一由定位样式计算。

### 7.3 短任务内容展示

日视图中短任务高度不足时，任务内容采用单行紧凑布局：

1. 任务块高度小于 `44px` 时启用单行展示。
2. 单行内容格式为 `标题 · HH:mm-HH:mm`。
3. 勾选圆点保留在左侧。
4. 编辑图标在短任务中隐藏，仅保留 hover 时可见或完全不展示，避免挤占空间。
5. 长任务继续使用标题和时间两行布局。
6. 该规则只影响视觉展示，不改变任务数据。

## 8. 数据模型

```ts
  title: string;
  done: boolean;
  progress: number;
  column_id: string;
  position: number;
  created_at: string;
  updated_at: string;
  scheduled_start_at: string | null;
  scheduled_end_at: string | null;
  reminder_minutes: number;
  completed_at: string | null;
  repeat_type: RepeatType;
  recurrence_series_id: string | null;
  recurrence_sequence: number | null;
  recurrence_origin_at: string | null;
  recurrence_detached: boolean;
}
```

### 8.2 CalendarTaskInput

```ts
export interface CalendarTaskInput {
  title: string;
  project?: string;
  column_id?: string;
  scheduled_start_at: string;
  scheduled_end_at: string;
  reminder_minutes?: number;
  repeat_type?: "none" | "daily" | "weekly" | "monthly" | "yearly";
```

1. `project` 为空时，后端按 `scheduled_start_at` 的日期自动生成 `YYYY-MM-DD` 分组。

## 11. 提醒能力

提醒逻辑从 `schedules` 切换为读取带时间属性的任务，并在应用级全局初始化，不能依赖用户停留在日程页：

1. 未完成任务才触发提醒。
2. 使用 `scheduled_start_at` 作为提醒基准。
3. 使用 `reminder_minutes` 控制提前提醒分钟数，默认值为 0。
4. 已提醒任务在当前页面生命周期内避免重复提醒。
5. 无计划开始时间的任务不参与日程提醒。
6. 每个重复实例独立提醒，提醒基于自身 `scheduled_start_at`，不维护系列级提醒状态。
7. 全局提醒在 `AppLayout` 初始化，周期性调用 `get_calendar_tasks` 读取当前时间附近的任务。
8. `reminder_minutes = 0` 表示不提醒，不触发系统通知。
9. `reminder_minutes > 0` 时，提醒触发窗口为“当前时间已到达 `scheduled_start_at - reminder_minutes`，且未超过任务开始后短暂宽限时间”，避免轮询间隔导致漏提醒。
10. 日程页只负责刷新当前时间指示线，不再维护独立提醒循环，避免打开日程页时重复提醒。

## 12. 浏览器开发环境兼容

非 Tauri 浏览器环境下：

1. `SchedulePage.vue` 使用 localStorage 保存日历任务。
2. `TasksPage.vue` 使用同一份 localStorage 数据构建本地看板。
3. 本地 key 为 `nalu-dev-calendar-tasks`。
4. 支持在 `localhost` 预览中验证新建、编辑、删除、完成和移出日程。
5. 任务页按 `scheduled_start_at` 优先计算日期分组，避免今天任务出现在错误分组或不可见。
6. 任务页 localStorage fallback 需要支持分组、列、Cmd/Ctrl 多选、批量完成、批量取消完成、批量删除撤销、批量移动和历史已完成日期分组隐藏。
7. 日程页 localStorage fallback 需要支持编辑面板分组选择、切换分组时更新 `project` 和 `column_id`、拖动已有任务修改时间。
8. 浏览器 fallback 只用于开发预览，不替代 Tauri/SQLite 作为正式运行数据源。

## 13. 旧日程过渡

旧 `schedules` 表不立即删除，第一版采用兼容保留：

1. 新建数据全部写入 `tasks`，不再新增 `schedules` 记录。
2. 旧 `schedules` 可在日程页只读展示。
3. 旧日程不进入任务页。
4. 旧日程不显示编辑、删除、重复、移出日程等增强操作按钮。
5. 第一版不实现旧日程迁移入口，只在文档中预留迁移方案。
6. 后续如提供迁移，必须由用户确认触发，不做应用启动时强制迁移。

后续可选迁移方案：

1. 用户确认后将旧 `schedules` 转为 `tasks`。
2. `scheduled_start_at = schedules.scheduled_at`。
3. `scheduled_end_at = scheduled_start_at + 1 小时`。
4. `project = scheduled_start_at` 对应日期分组。
5. `done = schedules.done`。
6. `reminder_minutes = schedules.reminder_minutes`。
7. 迁移后需记录映射，避免重复迁移。

33. 打开日视图和周视图，确认页面默认滚动到当前时间点所在小时单元格附近。
34. 新建日程任务时确认提醒默认值为 0，且 0 表示不提醒。
35. 将提醒分钟数设置为大于 0 后，确认离开日程页也能收到全局日程提醒。
36. 运行 `pnpm check`、`pnpm build`，并运行 Rust 测试或编译检查。

## 16. 注意事项

1. 不继续扩展 `schedules` 表作为主数据源，否则任务页和日程页会产生双写一致性问题。
2. 时间字符串继续使用本地时间，避免无意引入 UTC 偏移。
3. 日历拖选要避免影响任务卡片点击、完成、删除按钮的事件冒泡。
4. 跨天任务视觉上可以拆片段，但数据层必须保持单条任务。
5. 新增任务默认分组和列必须与任务页看板规则一致。
6. 更新任务页查询时要同步更新所有 `SELECT` 字段，避免 Rust 结构体和 SQL 列数不一致。
7. 数据库迁移必须幂等，避免老用户启动应用时重复 `ALTER TABLE` 失败。
8. 重复任务不要使用前端虚拟展开，必须生成真实任务实例，保证任务页和日程页同步。
9. 取消“这一项及未来重复”时，必须保留历史和已完成任务，避免破坏用户记录。
10. 任务页默认隐藏未来重复实例只是展示过滤，不改变数据库记录。
11. 日程页删除任务必须明确是删除 `tasks` 记录；移出日程必须只清空时间和重复关系。
12. 旧 `schedules` 迁移必须由用户确认触发，不做强制自动迁移。
13. 月视图点击日期不再进入日视图，避免与新建任务入口冲突。
14. 日程页批量修改重复任务时，不批量修改分组、列、排序和完成状态。
15. 周视图事件层必须与七天表头和小时网格保持同一列宽。
16. 日/周事件块外层不应使用额外 padding 造成视觉越界，边界缩进应统一由定位样式计算。
17. 看板数据归属自愈只修复组织字段，不应修改任务时间、完成状态和重复系列字段。
18. 日程页选择分组不等于选择分列，分列仍由任务页负责。
19. 拖动已有任务修改时间不能触发新建任务拖选逻辑。
20. 拖动已有任务时，右侧预留新建区域仍应可用于创建任务。
21. 批量删除必须支持撤销，且恢复原列和原排序。
22. 历史已完成日期分组隐藏只是展示过滤，不删除数据。
23. 搜索必须能找到被默认隐藏的历史已完成任务。
24. 任务页今天定位按钮在非搜索状态下常驻显示，必须能展开并滚动到今天分组。
25. 批量移动首期通过浮动栏选择目标列，不做多任务拖拽。
26. 日程页不提供批量移动；移动时间仅通过拖动单个任务完成。
27. “显示未来重复任务”和“显示历史已完成分组”属于展示设置，应放在任务页右上角设置面板内。
28. 任务列和任务独立存在，隐藏历史空分组不能删除列数据。
29. 日程提醒默认值为 0，0 必须被解释为“不提醒”，不能被解释为“开始时提醒”。
30. 日程提醒是应用级能力，不应绑定在日程页组件生命周期内。
31. 日/周视图默认定位当前时间只调整滚动位置，不改变锚点日期和视图范围。
