# 仪表盘设计文档

## 1. 界面概述

仪表盘是用户每天打开 Nalu 后最先接触的工作台。页面聚合任务、笔记、剪贴板、番茄钟、闹钟、AI 助手等高频入口，并提供快速操作能力。

## 2. 功能模块

1. 顶部欢迎信息：展示仪表盘标题和用户显示名称，支持编辑显示名称。
2. 快捷控制：提供提示音量、剪贴板监听、番茄钟快捷开关。
3. 快捷导航：提供核心模块入口。
4. 专注与最近要处理：展示番茄钟状态和最近要处理任务摘要。
5. 闹钟：展示活跃闹钟并支持快速开关。
6. 数据统计：展示任务、笔记、最近要处理数量。
7. 剪贴板：展示最近剪贴板内容并支持复制。
8. 最近要处理：展示未完成任务，并显示处理时间。
9. 最近笔记：展示最近笔记摘要。
10. AI 助手：提供首页 AI 对话入口。

## 3. 页面布局

页面采用纵向工作台布局。顶部欢迎区域固定在页面顶部，不参与排序；下方主要控制区域可在编辑模式中调整顺序。桌面端展示完整区域，移动端按平台能力隐藏桌面专属区域。

## 4. 数据模型

业务数据来自既有 Tauri commands：

1. `get_tasks`
2. `get_notes`
3. `get_clipboard_history`
4. `get_alarms`
5. `pomodoro_get_state`

布局顺序保存在本地：

```text
nalu-dashboard-widget-order-v1
```

数据格式为 widget ID 数组。

## 5. 接口清单

本页面复用既有接口，不因布局编辑新增后端接口。

## 6. 权限设计

仪表盘是本地个人工作台，不涉及权限点和角色配置。

## 7. 控制区域位置编辑设计细节

### 7.1 需求概述

当前仪表盘页面按固定顺序展示多个控制区域。用户希望“仪表盘中目前每一个控制区域修改为可以编辑位置的，参考手机桌面”。核心诉求是让仪表盘从固定排版变为可自定义区域顺序的工作台，用户可以进入编辑模式后像整理手机桌面图标一样拖动模块，调整常用区域的位置。

目标：

1. 仪表盘每个主要控制区域支持位置编辑。
2. 支持进入/退出布局编辑模式。
3. 编辑模式下支持拖拽排序，交互参考手机桌面：长按/拖动、目标占位、释放后落位。
4. 用户调整后的布局需要持久化，重新打开应用后保持。
5. 支持恢复默认布局。
6. 不改变各控制区域的原有业务能力和数据来源。
7. 桌面端与移动端均可使用，移动端需优先保障触控拖拽体验。

非目标：

1. 本次不做区域大小自由缩放。
2. 本次不做跨页面添加/删除小组件市场。
3. 本次不新增后端接口或数据库表。
4. 本次不改变任务、笔记、闹钟、剪贴板等业务数据模型。

### 7.2 可编辑区域定义

将仪表盘中的主要内容抽象为 `DashboardWidget`，每个区域拥有稳定 ID、标题、可见性和默认排序等元信息。

首期纳入以下区域：

| 区域 ID | 区域名称 | 当前页面内容 | 是否可移动 | 备注 |
| --- | --- | --- | --- | --- |
| `quickControls` | 快捷控制 | 音量、剪贴板监听、番茄钟快捷开关 | 是 | 保持内部布局不拆分 |
| `quickNav` | 快捷导航 | 模块入口宫格 | 是 | 内部入口顺序本次不改 |
| `focusAndNext` | 专注与最近要处理 | 番茄钟摘要、最近要处理任务卡片 | 是 | 桌面端显示；移动端按现有规则隐藏桌面专属内容 |
| `alarms` | 闹钟 | 活跃闹钟列表 | 是 | 桌面端显示 |
| `stats` | 数据统计 | 任务、笔记、最近要处理数量 | 是 | 保持当前响应式列数 |
| `clipboard` | 剪贴板 | 最近剪贴板内容 | 是 | 桌面端显示 |
| `nextTasks` | 最近要处理 | 最近要处理任务列表 | 是 | 包含处理时间 |
| `recentNotes` | 最近笔记 | 最近笔记卡片 | 是 | 保持当前展示数量 |
| `aiWidget` | AI 助手 | `AiChatWidget` | 是 | 作为区域参与排序 |

顶部欢迎标题作为页面头部，不参与排序，避免用户把页面身份信息拖到中间导致可读性下降。

### 7.3 布局编辑模式

新增仪表盘布局编辑模式，状态为 `dashboardLayoutEditing`。

入口设计：

1. 仪表盘标题行右侧新增“编辑布局”按钮。
2. 进入编辑模式后按钮区切换为：
   - “完成”：退出编辑模式并保留当前布局。
   - “恢复默认”：恢复默认区域顺序。
3. 移动端可通过同一按钮进入编辑模式，按钮需足够可点。

编辑模式视觉表现：

1. 每个区域外层出现细边框、轻微背景强调和拖拽手柄。
2. 区域右上角展示拖拽手柄图标，使用 lucide `GripHorizontal`。
3. 被拖动的区域降低透明度，目标位置显示占位条。
4. 非编辑模式下保持现有视觉，避免让仪表盘变重。

### 7.4 拖拽排序交互

交互参考手机桌面，但适配当前纵向工作台：

1. 编辑模式下，用户按住区域拖拽手柄。
2. 指针移动超过阈值后进入拖动状态，避免普通点击误触。
3. 拖动过程中根据指针所在区域计算目标位置。
4. 释放后将拖动区域插入目标位置。
5. 排序立即保存到本地持久化。
6. 点击“完成”退出编辑模式。

桌面端支持鼠标和触控板 pointer 事件。移动端支持触控 pointer 事件，并复用现有 `vibrate` 提供轻微震动反馈。

### 7.5 持久化设计

采用 localStorage 保存用户布局，不新增后端表。

Key：

```text
nalu-dashboard-widget-order-v1
```

数据结构：

```json
["quickControls", "quickNav", "focusAndNext", "alarms", "stats", "clipboard", "nextTasks", "recentNotes", "aiWidget"]
```

读取规则：

1. 页面初始化时读取 localStorage。
2. 仅保留当前版本存在的合法 widget ID。
3. 对于新增但旧布局没有的 widget，按默认顺序追加到末尾。
4. 对于已删除或当前平台不可见的 widget，不渲染，但不阻塞布局加载。
5. 解析失败时回退默认顺序。

保存规则：

1. 每次拖拽落位后保存。
2. 点击“恢复默认”时移除 localStorage key。
3. 不依赖网络和同步状态。

### 7.6 平台与可见性

部分区域当前只在桌面端显示，例如闹钟、剪贴板、时间关键区域中的桌面内容。布局排序分离“全量顺序”和“当前可见区域”：

1. `widgetOrder` 保存全量顺序。
2. `visibleDashboardWidgets` 根据 `isMobile` 等条件过滤。
3. 拖拽时仅对当前可见区域重排。
4. 保存时将当前可见区域按新顺序写回全量顺序，其它不可见区域保持原位置。

### 7.7 前端内部接口

本功能不新增 Tauri command 或 HTTP 接口，仅新增前端内部类型和函数。

核心类型：

```ts
type DashboardWidgetId =
  | 'quickControls'
  | 'quickNav'
  | 'focusAndNext'
  | 'alarms'
  | 'stats'
  | 'clipboard'
  | 'nextTasks'
  | 'recentNotes'
  | 'aiWidget'

interface DashboardWidgetDefinition {
  id: DashboardWidgetId
  titleKey: string
  desktopOnly?: boolean
}
```

核心函数：

| 函数 | 说明 |
| --- | --- |
| `loadDashboardWidgetOrder()` | 从 localStorage 读取并规范化顺序 |
| `saveDashboardWidgetOrder(order)` | 保存顺序 |
| `resetDashboardWidgetOrder()` | 恢复默认顺序 |
| `visibleDashboardWidgets` | 根据平台过滤并按顺序返回 widget |
| `moveDashboardWidget(sourceId, targetId, position)` | 调整区域位置 |
| `onWidgetPointerDown(event, widgetId)` | 开始拖拽 |
| `onWidgetPointerMove(event)` | 更新拖拽目标 |
| `onWidgetPointerUp(event)` | 释放并保存 |

### 7.8 数据库与权限

本功能不涉及数据库结构修改，不需要 SQL 迁移脚本。

本功能为本地个人仪表盘布局配置，不涉及用户权限、角色权限或后端鉴权。
