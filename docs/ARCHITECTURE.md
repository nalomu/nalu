## 详细清单

### Desktop Client（macOS / Windows）

运行在用户设备上，**离线也能完整使用**（同步功能除外）。

| 模块 | 技术 | 说明 |
|------|------|------|
| 应用壳 | Tauri 2.11.2 | 进程管理、窗口管理、系统托盘、桌面打包 |
| UI 渲染 | Vue 3 + Vue Router + 系统 WebView | 所有界面（命令面板、设置、各功能页） |
| 状态 | Pinia | 全局警报、剪贴板监听、语言和 AI 配置 |
| 样式 | Tailwind CSS 4 | 组件样式 |
| Markdown 编辑 | Milkdown 7.21 | 笔记/任务的富文本编辑 |
| 本地数据库 | SQLite (rusqlite 0.40) | 任务、笔记、日程、配置等所有结构化数据 |
| MySQL 客户端 | mysql_async 0.37 | 连接用户的本地 MySQL 做导入导出 |
| 剪贴板 | tauri-plugin-clipboard-manager | 系统剪贴板读写 |
| 全局热键 | tauri-plugin-global-shortcut | Cmd+Space 唤起命令面板 |
| 系统通知 | tauri-plugin-notification | 番茄钟提醒、闹钟、日程提醒 |
| 文件操作 | tauri-plugin-fs + dialog | Markdown 文件读写、目录选择 |
| 插件系统 | Rust 自研 | 插件加载、命令注册、插件间通信 |
| CRDT 客户端 | automerge 0.10 | 生成/应用变更集，本地数据副本 |
| AI 调用 | reqwest (HTTP) | 调用本地 Ollama 或云端 API |
| 定时器/闹钟 | tokio + tauri-plugin-notification | 番茄钟倒计时、日程定时触发 |

Desktop Rust Core 是桌面端实现细节，不作为 Android/iOS 的共享后端。移动端只共享协议、
数据模型、同步规则和错误码。

### Android Client（后续）

正式 Android 端走 Kotlin / Jetpack Compose 原生路线，不把 Tauri Android 作为主线。

| 模块 | 技术 | 说明 |
|------|------|------|
| UI | Jetpack Compose | 移动端原生交互和系统适配 |
| 本地数据 | Room / SQLite | 任务、笔记、日程等本地副本 |
| 同步客户端 | Kotlin 实现 | 按 `shared/contracts/` 契约收发 HTTP changelog 同步消息 |
| 系统能力 | Android 原生 API | 通知、分享入口、快捷入口、后台策略、权限生命周期 |

正式 Android 工程位于 `mobile/android/`。
Android v1 的日程写入任务表的计划时间字段，旧 `schedules` 表仅保留兼容历史数据。

### iOS Client（暂搁置）

iOS 先作为轻端方向保留，等桌面端和 Android 同步链路稳定后再启动。

| 模块 | 技术 | 说明 |
|------|------|------|
| UI | SwiftUI | 任务、笔记、日程的查看和轻量编辑 |
| 本地数据 | SQLite / CoreData / SQLite.swift | 本地副本 |
| 系统集成 | Share Extension / Shortcuts | 分享到 Nalu、快捷指令 |
| 同步客户端 | Swift 实现 | 按 `shared/` 契约收发同步消息 |

### Shared Contracts

`shared/` 是跨端契约中心，职责是描述“数据和协议”，不是承载三端 UI 或桌面 Rust Core。

| 内容 | 说明 |
|------|------|
| 数据模型 | 任务、笔记、日程、同步状态等字段定义 |
| 同步消息 | 变更集、设备状态、游标、冲突处理规则 |
| 错误码 | 认证、同步、数据校验、网络异常等统一错误 |
| 导入导出 | 备份、迁移、跨端交换格式 |
| 设计 token | 颜色、字号、间距等跨端视觉契约 |

### Server 端（Linux VPS / 自建服务器）

只部署两个服务，**都极其轻量**。

| 模块 | 技术 | 说明 |
|------|------|------|
| 同步服务 | axum 0.8.9 + HTTP | `/api/auth/pair`、`/api/sync/push`、`/api/sync/pull` |
| 变更集存储 | SQLite | 存储业务表快照和 `server_changelog`，按 `last_server_ts` 拉取 |
| Ollama（可选） | Ollama + 开源模型 | AI 推理服务，仅当你 VPS 有足够算力时部署 |

### 不在 Server 端运行的东西

| 东西 | 为什么不在 Server |
|------|------------------|
| SQLite 主数据库 | 本地优先，数据在设备上 |
| 业务逻辑 | 全在客户端 Rust 后端 |
| 文件存储（.md） | 本地文件系统 |
| MySQL 操作 | 直连用户本地 MySQL |
| UI 渲染 | 桌面 WebView / 移动端原生 UI |
| 插件运行时 | 桌面客户端进程内或子进程 |

## 数据流向

```
用户在桌面端添加一个待办
        │
        ▼
   Vue UI ──IPC──► Rust 后端
        │                │
        │                ├──► SQLite 写入（本地持久化）
        │                │
        │                └──► sync_changelog 记录本地变更
        │                         │
        │                         ▼
        │              HTTP POST /api/sync/push
        │                         │
        │                         ▼
        │              其他设备 HTTP POST /api/sync/pull 拉取
        │                         │
        │                         ▼
        │              Android/iOS 原生客户端收到变更集
        │                         │
        │                         ▼
        │              按共享协议应用变更 → 本地 SQLite/Room/CoreData 更新
        │                         │
        │                         ▼
        └──────────────────── 移动端 UI 刷新
```

## Server 部署规格参考

HTTP 同步服务非常轻，最便宜的 VPS 就能跑：

| 指标 | 要求 |
|------|------|
| CPU | 1 核足够 |
| 内存 | 128 MB 足够 |
| 磁盘 | 1 GB（变更集很小，定期清理） |
| 带宽 | 极低（只传 changelog payload） |
| 系统 | Ubuntu 22.04+ / Debian 12+ |
| 端口 | 443 (HTTPS/WSS) |

Ollama 如果部署在 Server 上，则需要 GPU 或至少 16GB 内存的 CPU 实例。
